# 공부 노트 스타일

노트의 독자는 한 명이다: **프론트엔드(React Native/Expo)만 해온 개발자**. Spring Bean, 영속성, DI, 트랜잭션을 하나도 모른다. 독자가 이미 아는 세계(FE)에서 다리를 놓아야 이해가 붙는다.

## 눈높이 원칙

- 백엔드 용어는 **처음 등장할 때 반드시 정의**한다. 이전 단계 노트에 정의가 있으면 `[[링크]]`로 대신한다.
- 가능한 곳마다 FE 대응물로 비유한다. 자주 쓰는 다리:

| 백엔드 개념 | FE에서 가장 가까운 것 (비유이며 완전 동치 아님) |
|---|---|
| IoC 컨테이너 / Bean | React 루트가 Context Provider들을 조립해두는 것 — 부품을 직접 new 하지 않고 주입받음 |
| DI (의존성 주입) | props/context로 의존을 내려받는 것. `useContext` ↔ `@Autowired`/생성자 주입 |
| 계층 (Controller/UseCase/도메인) | 화면 컴포넌트 / 커스텀 훅 / 순수 유틸 함수의 분리 |
| 영속성 컨텍스트 | React Query 캐시 — 같은 키를 두 번 조회하면 캐시가 답하고, 변경은 모아뒀다 flush |
| DTO | API 응답 타입 vs 화면 상태 타입을 분리하는 것 |
| 스레드풀 vs 이벤트루프 | Node는 싱글 스레드 이벤트루프, JVM 서버는 요청당 스레드를 풀에서 꺼내 씀 |
| Gradle 멀티모듈 | pnpm workspace / 모노레포 패키지 |

- 비유는 반드시 "어디까지 같고 어디서부터 다른지" 한 줄을 붙인다. 비유만 남고 실제 동작이 틀리면 역효과다.
- 한 문단 하나의 개념. 3개 이상 새 용어가 한 문단에 나오면 쪼갠다.

## 노트 구조

볼트 템플릿(`_templates/📝 공부노트 템플릿.md`) 골격을 따른다: **한 줄 요약 → 개념표 → 원리 → 비유 → (실코드 예시) → 주의점/트러블슈팅 → 치트시트 → 용어집 → 체크리스트**. 요청 흐름 노트는 code-flow-writer 정의의 흐름 골격을 우선한다.

frontmatter:
```yaml
tags: [kbap-backend, <주제>]
생성일: YYYY-MM-DD
상태: 완료
```

## 실코드 인용 규칙

- 인용은 **실제 파일에서 발췌**하고 `경로:줄` 표기(예: `app/api/src/main/kotlin/.../MemberController.kt:42`). 기억으로 재구성한 가짜 코드를 실코드처럼 제시하지 않는다. 일반 예시 코드는 "예시" 라고 명시한다.
- kbap-server는 Kotlin 주석 금지 레포다. 발췌문에 주석을 추가하지 말고, 발췌 **아래에** 줄 단위 풀이를 쓴다.
- 발췌는 15줄 이내로 자른다. 길면 핵심 줄만 남기고 `…`.

## Obsidian 표기 규약 (볼트 규칙 §5)

- 표 안 별칭 링크는 `[[대상\|별칭]]` — 파이프 이스케이프 필수.
- 문법 예시용 가짜 링크는 백틱으로 감싼다.
- `[[링크]]`는 대상 파일명과 **글자까지 정확히 일치**해야 한다. 쓰기 전에 대상 파일명을 확인한다.
- **레포 문서(ADR·conventions 등) 참조에 마크다운 상대링크를 쓰지 않는다** — `[ADR-0008](../adr/....md)`처럼 쓰면 볼트 밖을 가리켜 옵시디언에서 깨진다(4단계 실사고, 10건 수리). 대신 인라인 코드로 레포 경로를 쓴다: ``ADR-0008(`docs/adr/0008-....md`)``.
- 파일명 = 노트 제목. 읽기 좋은 한국어(대시 나열식 금지).
- **kbap 백엔드/ 노트는 공부 순서 번호 접두를 붙인다**: `N. 제목` (예: `15. 소셜 로그인 흐름 — …`). 사이드바 가나다순에서 학습 순서가 보이게 하려는 사용자 요청(2026-07-15, 기존 16노트 일괄 리네임). 새 노트의 번호는 계획서가 지정하며, 폴더의 마지막 번호에 이어 붙인다. H1 제목도 파일명과 동일하게 번호 포함.
