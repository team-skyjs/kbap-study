# kbap 공부 하네스 오케스트레이터

목표: FE 개발자인 사용자가 kbap-server에 합류하기 위한 공부 노트를 **단계별로** iCloud 볼트 `kbap 백엔드/`에 생성한다. 사용자와 합의된 방식: 한 실행 = 한 단계(노트 2~4개), 사용자가 읽고 "다음 단계"를 요청하면 이어간다.

**실행 모드: 하이브리드** — 계획(서브, 동기) → 작성(에이전트 팀: 이름 붙인 병렬 에이전트 + SendMessage 자체 조율) → 장부정리(서브, 동기). 모든 Agent 호출에 `model: "opus"`를 명시한다.

## Phase 0: 컨텍스트 확인 (실행 모드 판별)

1. 공부 지도 확인: iCloud 볼트 `kbap 백엔드/🗺️ kbap 백엔드 공부 지도.md`
   - **없으면** → 초기 실행(1단계 + 지도 생성부터).
   - **있으면** → 체크 상태에서 다음 미완료 단계 판별.
2. `.Codex/workspace/stage-{N}-plan.md` 존재 + 사용자가 부분 보완 요청 → **부분 재실행**: 해당 노트의 작성자만 재호출(재호출 지침에 따라 Edit), 이후 vault-keeper만 재실행.
3. 사용자가 특정 주제를 지목하면("스캔 흐름부터") 단계 순서보다 사용자 지목을 우선하고, 선행 개념이 빠지면 실행 전에 알린다.

## Phase 1: 계획 (서브 에이전트, 동기)

- `curriculum-architect` 호출(에이전트 정의: `.Codex/agents/curriculum-architect.md`): 이번 단계 번호와 지도 상태를 prompt에 담는다.
- 산출: `.Codex/workspace/stage-{N}-plan.md` (+ 초기 실행이면 공부 지도 노트).
- 계획서의 노트 제목 목록을 사용자에게 한 줄로 보고하고 곧장 Phase 2로 간다(승인 대기 없음 — 단계 단위 합의는 이미 사용자와 됨).

## Phase 2: 작성 (에이전트 팀, 병렬)

- 계획서의 담당 배정대로 노트별 작성자를 **이름 붙여 병렬 스폰**한다: `Agent(name: "writer-<슬러그>", subagent_type: "general-purpose", model: "opus", run_in_background: true)`. prompt에는 (a) 자기 에이전트 정의 파일 경로, (b) 계획서 경로와 담당 노트 제목, (c) 팀 동료 이름 목록(SendMessage 대상)을 담는다.
  - 개념 노트 → `concept-writer` 정의 사용, 흐름 노트 → `code-flow-writer` 정의 사용.
- 팀 통신: 작성자끼리 겹침 조율은 SendMessage로 자체 해결. 오케스트레이터는 개입하지 않고 완료 알림만 수집한다.
- 동시 작성자는 최대 4명(한 단계 노트 수 상한과 동일).

## Phase 3: 장부정리 (서브 에이전트, 동기)

- 모든 작성자 완료 후 `vault-keeper` 호출: 작성자들의 응답(노트 경로 + 링크 목록)을 전달.
- ④복리 → ⑤홈/지도 등록 → ⑥로그 → 단계 린트. 반려 항목이 나오면 해당 작성자를 1회 재스폰해 수정 후 vault-keeper 부분 재실행.

## Phase 4: 마무리 보고

- 사용자에게: 생성 노트 목록(한 줄 요약씩), 복리로 갱신된 기존 노트, 다음 단계 예고, "다 읽으면 '다음 단계'라고 해주세요".
- 피드백 기회 제공: 눈높이·분량·비유 스타일에 고칠 점이 있는지 묻는다. 같은 유형 피드백 2회 반복 시 이 하네스(스킬/에이전트 정의) 수정을 제안한다.

## 데이터 전달

- 계획: `.Codex/workspace/stage-{N}-plan.md` (파일)
- 작성자 → vault-keeper: Agent 반환값(노트 경로 + 링크 목록) + 볼트의 노트 파일 자체
- 작성자 ↔ 작성자 / ↔ architect: SendMessage
- 중간 산출물(`workspace/`)은 보존한다(부분 재실행·감사용).

## 에러 핸들링

- 작성자 1명 실패/무응답 → 1회 재스폰. 재실패 시 그 노트를 빼고 진행하되 마무리 보고에 누락을 명시하고 지도에 미완료로 남긴다.
- 계획서의 근거 파일이 실제 레포와 다르면 작성자가 실측 우선(에이전트 정의에 내장) — 오케스트레이터는 보고만 취합.
- iCloud 경로 접근 실패(동기화 잠금 등) → 재시도 1회 후, 실패 시 `.Codex/workspace/`에 임시 저장하고 사용자에게 수동 이동을 요청한다.
- kbap-server에 쓰기가 필요해 보이는 상황은 무조건 중단하고 사용자에게 보고한다(읽기 전용 불변).

## 테스트 시나리오

- **정상**: "다음 단계 진행해줘" → 지도에서 2단계 판별 → 계획서 → writer 3명 병렬 → vault-keeper ④⑤⑥+린트 → 보고. 확인: 볼트에 노트 3개, 홈/지도 갱신, 로그 2줄 append, 깨진 링크 0.
- **부분 보완**: "JPA 노트 비유가 어려워, 더 쉽게" → Phase 0에서 부분 재실행 판별 → 해당 노트 작성자만 재호출(Edit) → vault-keeper 린트만 → 보고. 확인: 다른 노트 무변경, 로그에 update 1줄.
- **에러**: 작성자 1명 무응답 → 1회 재스폰 후 실패 → 나머지 노트로 ④⑤⑥ 진행, 보고에 "노트 X 누락, 지도에 미완료 표시" 명시.
