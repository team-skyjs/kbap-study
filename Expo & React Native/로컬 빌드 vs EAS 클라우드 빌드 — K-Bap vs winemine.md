# 로컬 빌드 vs EAS 클라우드 빌드 — K-Bap vs winemine

> 맥락: winemine 개발 시작할 때 "왜 이번엔 Xcode를 열어야 하지? K-Bap 땐 안 그랬는데?"가 헷갈려서 정리.
> 목표: **"Dev Build를 만드는 방법이 2가지"** 라는 걸 확실히 이해하기.

---

## 0. 한 줄 요약
**[[EAS Dev Build vs Expo Go|Dev Build]](=내 개발용 앱)를 만드는 공장이 두 곳이다.**
- **EAS 클라우드 빌드** = Expo 서버가 대신 컴파일 + 애플 인증서도 클라우드에서 자동 처리 (Xcode 안 봄) → **K-Bap 방식**
- **로컬 빌드** = 내 Mac의 Xcode가 직접 컴파일 + 인증서도 내 Mac에서 설정 → **winemine 방식**

> [!important] 제일 중요한 오해 풀기
> K-Bap 때 "아무것도 안 한 것처럼" 느낀 건, 진짜 할 게 없어서가 아니라 **EAS가 뒤에서 다 해준 것**이에요.
> 애플 인증서 만들기·보관 같은 귀찮은 일을 클라우드가 대신 처리했을 뿐, 그 단계 자체가 사라진 건 아니에요.

---

## 1. 핵심 비교표

| | **K-Bap** (지금까지) | **winemine** (이번 방식) |
|---|---|---|
| dev client 빌드 | **EAS Build (클라우드)** | **로컬 빌드** (`npx expo run:ios`) |
| 컴파일 위치 | Expo 서버 | 내 Mac의 Xcode |
| 서명(인증서) | EAS가 클라우드에서 자동 | 내 Mac에서 직접 설정 |
| Xcode | 안 열어도 됨 | **한 번은 열어야 함** |
| 비용/속도 | 클라우드 큐 대기 | 무료, 이후 제일 빠름 |
| 명령 | `eas build --profile development` | `npx expo run:ios` |

---

## 2. 왜 방법이 2개나 있나? (개념)

`★ 핵심 개념 ─────────────────────────────`
Dev Build를 폰에 깔려면 **① 네이티브 코드를 컴파일**하고 **② 애플 서명(인증서)** 을 붙여야 한다.
이 둘을 **"누구 컴퓨터에서 하느냐"** 가 로컬 vs 클라우드의 차이 전부다.
- 클라우드(EAS): Expo 서버가 ①②를 대신 → 내 Mac은 명령만 침
- 로컬: 내 Mac의 Xcode가 ①②를 직접 → 내 Mac에 Xcode·인증서 세팅 필요
결과물(폰에 깔리는 dev client 앱)은 **양쪽 다 똑같다.** 만드는 공장만 다를 뿐.
`──────────────────────────────────────`

> 비유: **케이크를 주문 제작(EAS) vs 집에서 직접 굽기(로컬).**
> - 주문(EAS): 전화 몇 통(=`eas login`)이면 완성품이 옴. 오븐·재료 신경 안 씀. 대신 **줄 서서 기다림**(클라우드 큐).
> - 직접(로컬): 내 오븐(Xcode)을 써야 하니 **처음 한 번 오븐 예열·세팅**(Team 선택→인증서)이 필요. 대신 그다음부턴 **제일 빠르고 공짜.**

---

## 3. "서명(인증서)"이 뭐길래

애플은 아무 앱이나 아이폰에 못 깔게 막아둠. **"이 앱은 등록된 개발자가 만들었고, 이 기기에 깔아도 된다"** 는 애플의 도장이 서명(코드 사이닝).

- **EAS**: 이 도장(인증서)을 **클라우드에서 대신 만들고 보관**해줌. 그래서 K-Bap 땐 이 과정이 안 보였음.
- **로컬**: 이 도장을 **내 Mac에서** 찍어야 함 → Xcode에서 "Team"(내 애플 개발자 계정)을 한 번 골라주면 Xcode가 인증서를 자동 생성.

> 즉 winemine에서 Xcode를 여는 유일한 이유 = **"Team 한 번 선택해서 서명 켜기"**. 그 한 단계뿐이에요.

---

## 4. 그래서 winemine은 어느 쪽? (선택지 A vs B)

> [!note] A. 로컬 빌드 마무리 (추천 — 이미 90% 됨)
> - Xcode에서 **Team 한 번 선택 → 인증서 자동 생성** (약 5분). 이후 제일 빠르고 무료.
> - `ios/` 폴더도 이미 생성됐고 기기도 잡혀서, **서명만 켜면 바로 테스트 가능.**
> - 이후엔 K-Bap처럼 `npx expo start --dev-client` 로만 돌아감.

> [!note] B. K-Bap처럼 EAS로 (Xcode 안 열기)
> - `eas build --profile development` → EAS가 서명 클라우드 처리. 익숙한 방식.
> - 단 현재 development 프로필이 **시뮬레이터용**(`ios.simulator: true`)이라 실물 기기용으로 바꿔야 하고, `eas device:create`로 이 아이폰을 등록해야 함. + 클라우드 큐 대기.

**결론**: 지금은 **A가 훨씬 빠름** (다 세팅됐고 서명 한 단계만 남음). "Xcode 절대 안 만지고 K-Bap과 똑같이" 원하면 B.

---

## 5. 다음에 헷갈리면 볼 체크리스트
1. "Dev Build 만드는 방법 2개" 기억: **EAS 클라우드** vs **로컬(Xcode)**.
2. 둘 다 하는 일은 같음 = 컴파일 + 애플 서명. **"어느 컴퓨터에서 하느냐"** 만 다름.
3. K-Bap이 "쉬웠던" 이유 = EAS가 서명을 클라우드에서 대신 처리해서.
4. 로컬은 처음 한 번 **Xcode에서 Team 선택**(서명 켜기)만 하면, 그 뒤론 제일 빠르고 무료.
5. 실물 기기 EAS 빌드는 `ios.simulator` 끄고 `eas device:create`로 기기 등록 필요.

---

## 6. 용어집
- **로컬 빌드**: 내 Mac의 Xcode가 직접 컴파일하는 방식 (`npx expo run:ios`).
- **EAS Build**: Expo 클라우드 서버가 대신 컴파일해주는 방식 (`eas build`).
- **코드 서명 / 인증서**: "등록된 개발자가 만든 앱"이라는 애플의 도장. 없으면 실기기 설치 불가.
- **Team**: Xcode에서 고르는 내 애플 개발자 계정. 이걸 골라야 인증서가 자동 생성됨.
- **ios.simulator: true**: EAS 프로필이 시뮬레이터용이라는 설정. 실기기엔 꺼야 함.

> [!note] 서명은 "설치 허가"를 넘어 "로그인 신원"이기도 하다 — Android (2026-07-20 추가)
> 이 노트의 서명 얘기는 iOS 인증서(설치 허가) 중심이었는데, Android에선 **어떤 keystore로 서명했느냐(SHA-1)가 구글 로그인의 앱 신원**이 된다. EAS 관리 keystore·로컬 debug keystore·Play 재서명 키가 각각 다른 신원이라, 빌드 경로가 바뀌면 로그인이 깨질 수 있다. K-Bap 실사고 → [[Android 구글 로그인 — SHA-1·OAuth 클라이언트·DEVELOPER_ERROR]]
