**⑥ 작성자 실측 요약**
- **배치 잡: 코드 2개, 기본 설정에서 실제 뜨는 건 1개.** `foodVectorSyncJob` 은 `kbap.vector.enabled` **and** `kbap.llm.embedding.enabled` 둘 다 true 여야 하는데 둘 다 기본 `false` → 매시 30분 `UnknownJob` 로그만 찍히고 넘어간다(에러 아님).
- **재시도·DLQ 는 두 아웃박스가 정반대다.** `food_content_outbox` — 상한·백오프·kbap 쪽 DLQ **전부 없음**, `attempts` 는 세기만 하고 **어떤 분기에도 안 쓰인다**, `SENT` 정체 시 자동 복구 없이 관리자 대시보드 건수로만 보인다. `food_vector_outbox` — `MAX_ATTEMPTS=5` 초과 시 `FAILED` 격리 + `last_error`(500자) + `retry()` 복구. **경계를 넘느냐(랭체인 책임)가 상태 기계를 갈랐다.**
- **벡터 저장소 실체: MySQL 이 아니라 AWS DocumentDB** (MongoDB 호환, `kbap.foods`, cosine, `$search`+`vectorSearch` — Atlas 의 `$vectorSearch` 와 다른 문법). MySQL 에 안 넣은 건 ANN 벡터 인덱스가 없어서.
- **임베딩 벤더 교체(Bedrock Titan → OpenAI 256) 때 재색인 배치를 하나도 안 만들었다.** ① 차원이 실제로는 안 바뀌었다 — 인덱스는 처음부터 256, Titan 은 Spring AI 2.0.0 이 `dimensions` 를 직렬화 못 해 **256을 보내려다 실패한 잠복 결함**(차원 검증 `check` 한 줄이 잡음). ② `embeddingHash = sha256(모델명\|차원\|원문)` 이라 **모델명이 바뀌는 순간 전 문서 해시가 불일치 → 다음 배치가 자동 재임베딩**. 대가는 음식 수 × 단가가 한 번에 청구되는 것. 관리자 enqueue 버튼은 `not exists(operation=UPSERT)` 라 **"전량 재색인" 이 아니라 "미등록분 백필"** 이다.
- ⚠️ **이름과 실제가 다른 자리 — 벡터 동기화는 SQS 큐를 타지 않는다.** 스펙 폴더명이 `kb-328-food-vector-outbox` 라 27번의 콘텐츠 아웃박스처럼 큐를 탈 것처럼 보이지만, 배치가 DB 행을 직접 읽어 임베딩을 만들고 DocumentDB 에 직접 적재한다 — SQS 도 다른 레포도 없다. **"아웃박스 = 큐" 로 외우면 틀린다.** 작성자 둘이 교차 확인해 27 §9·§18 과 28 §5 에 반영됨.
