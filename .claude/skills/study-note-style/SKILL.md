# 공부 노트 스타일

노트의 독자는 한 명이다. **2026-09-03 사용자 피드백으로 독자 상을 정정했다** — 아래가 정본이다.

> **자바로 CRUD API 를 아주 살짝 짜 본 사람.** 본인 표현으로 *"JSON 상하차만 해봤다"*.
> - `@RestController`·`@Service` 를 **붙여는 봤다.** 그런데 그게 무슨 뜻인지, 스프링이 뒤에서 뭘 하는지는 **전혀 모른다.**
> - **내부 동작은 아예 모른다고 전제하라** — 빈·싱글턴·컨테이너·영속성 컨텍스트·스레드풀 전부 처음 듣는 말이다.
> - 주력은 프론트엔드(React Native/Expo)지만 **TypeScript 전문가가 아니다.**

**⛔ TypeScript·JavaScript 와의 비교를 쓰지 마라.** (2026-09-03 지시: *"ts js랑 비교는 걍 빼버려"*)
- `strictNullChecks`·트랜스파일·이벤트루프·`useEffect`·npm 같은 대비는 **설명이 아니라 또 하나의 장벽**이다. 독자가 그쪽도 깊이 알지 못한다.
- 대신 **① 자바에서 본 적 있는 것**(애너테이션·클래스·`new`)에서 출발하거나, **② 코드와 무관한 일상 비유**를 쓴다.
- 어쩔 수 없이 언급해야 하면 **한 줄 이하**로, 그리고 **모르면 건너뛰어도 되는 곁가지**임을 밝힌다.

## 눈높이 원칙

- 백엔드 용어는 **처음 등장할 때 반드시 정의**한다. 이전 단계 노트에 정의가 있으면 `[[링크]]`로 대신한다.
- **"다음 노트가 정본"이라며 넘기지 마라.** 지금 읽는 사람은 그 노트를 아직 안 읽었다. 최소 정의(2~4줄 상자)를 **여기서 주고** 링크를 건다. (2026-09-03 사고: 노트2 §7 이 아직 안 나온 4번의 "빈" 개념을 전제해 독자가 막혔다.)
- **한 문단에 새 용어를 두 개 이상 넣지 마라.** 새 개념 하나 → 그게 뭔지 → 왜 필요한지 → kbap 실물, 순서로 간다.
- 가능한 곳마다 FE 대응물로 비유한다. 자주 쓰는 다리:

> [!warning] 아래 대비표는 **폐기**됐다 (2026-09-03)
> 이전 버전 스킬에는 "백엔드 개념 ↔ FE 대응물" 표가 있었고 R1~R10 노트가 그걸 따랐다. **독자 상 정정으로 무효**다. 새 노트는 쓰지 말고, 기존 노트를 보완할 때는 **자바 경험 또는 일상 비유로 교체**한다.

- 비유는 반드시 "어디까지 같고 어디서부터 다른지" 한 줄을 붙인다. 비유만 남고 실제 동작이 틀리면 역효과다.
- 한 문단 하나의 개념. 3개 이상 새 용어가 한 문단에 나오면 쪼갠다.

## 노트 구조

볼트 템플릿(`_templates/📝 공부노트 템플릿.md`) 골격을 따른다: **한 줄 요약 → 개념표 → 원리 → 비유 → (실코드 예시) → 주의점/트러블슈팅 → 치트시트 → 용어집 → 체크리스트**. 요청 흐름 노트는 code-flow-writer 정의의 흐름 골격을 우선한다.

머리말(제목 위 `> [!info] 관련 노트` 콜아웃)은 **두 줄 고정 서식**을 쓴다 — 폴더 안에서 서식이 갈리면 사이드바·미리보기에서 노트가 다른 시리즈처럼 보인다:

```markdown
> [!info] 관련 노트
> 🏠 [[🏠 홈]] · 📂 주제: [[🗺️ kbap 백엔드 공부 지도 (2026-08)]]
> ⬅️ 앞: [[N-1. …]] · ➡️ 다음: [[N+1. …]]
> 🔗 곁: [[…]]        ← 선택. 다른 주제 폴더의 관련 노트가 있을 때만
```

- 아직 집필되지 않은 앞/다음 노트는 **위키링크 대신 `제목(집필 예정)` 일반 텍스트**로 쓴다(유령 노드 방지). 그 노트가 완성되는 회차에 vault-keeper 가 링크로 승격한다.
- `📂 주제:` 자리에는 폴더명이 아니라 **지도 노트 링크**를 넣는다 — 폴더는 사이드바에 이미 보이고, 독자에게 필요한 건 목차로 돌아가는 길이다.

제목(H1) 바로 아래도 **고정 블록**이다 — 절 번호는 반드시 `## 0. 한 줄 요약` 부터 시작한다(인라인 `> **한 줄 요약**` 으로 대체하지 않는다):

```markdown
# N. 제목

> 작성: YYYY-MM-DD · 맥락: (이 노트가 왜 이 자리에 있는지 — 앞 노트에서 무엇이 남았는지)
> 목표: (읽고 나면 무엇을 말할 수 있게 되는지)

---

## 0. 한 줄 요약
```

frontmatter:
```yaml
tags: [kbap-backend, <주제>]
생성일: YYYY-MM-DD
상태: 완료
```

## 실코드 인용 규칙

- 인용은 **실제 파일에서 발췌**하고 `경로:줄` 표기(예: `app/api/src/main/kotlin/.../MemberController.kt:42`). 기억으로 재구성한 가짜 코드를 실코드처럼 제시하지 않는다. 일반 예시 코드는 "예시" 라고 명시한다.
- kbap-server는 Kotlin 주석 금지 레포다. 발췌문에 주석을 추가하지 말고, 발췌 **아래에** 줄 단위 풀이를 쓴다.
- 발췌는 15줄 이내로 자른다. 길면 핵심 줄만 남기고 `…`.

## 응답 JSON 예시 규칙 (실측 대조 의무)

노트에 API 응답 JSON 을 적을 땐 **반드시 `common/src/main/kotlin/com/kbap/common/core/error/`·`api/src/main/kotlin/com/kbap/api/core/BaseResponse.kt` 를 열어 필드명을 대조**한다. 기억으로 쓰지 않는다.

- kbap 공통 봉투는 **`success` · `payload` · `message` · `code`** 4필드다. **`data`·`error` 필드는 존재하지 않는다.**
- 흔한 사고: 다른 프로젝트 관행대로 `"data"` 라고 적는 것. **2026-08 재구축에서만 두 번 나왔다**(노트22 §9, 노트27 §13). FE 가 노트를 베끼면 `undefined` 가 나오는 종류의 오류다.
- 에러 코드(`AUTH-003` 등)도 `ErrorCode.kt` 를 열어 **실재하는 코드만** 인용한다.

## Obsidian 표기 규약 (볼트 규칙 §5)

- 표 안 별칭 링크는 `[[대상\|별칭]]` — 파이프 이스케이프 필수.
- 문법 예시용 가짜 링크는 백틱으로 감싼다.
- `[[링크]]`는 대상 파일명과 **글자까지 정확히 일치**해야 한다. 쓰기 전에 대상 파일명을 확인한다.
- **레포 문서(ADR·conventions 등) 참조에 마크다운 상대링크를 쓰지 않는다** — `[ADR-0008](../adr/....md)`처럼 쓰면 볼트 밖을 가리켜 옵시디언에서 깨진다(4단계 실사고, 10건 수리). 대신 인라인 코드로 레포 경로를 쓴다: ``ADR-0008(`docs/adr/0008-....md`)``.
- 파일명 = 노트 제목. 읽기 좋은 한국어(대시 나열식 금지).
- **kbap 백엔드/ 노트는 공부 순서 번호 접두를 붙인다**: `N. 제목` (예: `15. 소셜 로그인 흐름 — …`). 사이드바 가나다순에서 학습 순서가 보이게 하려는 사용자 요청(2026-07-15, 기존 16노트 일괄 리네임). 새 노트의 번호는 계획서가 지정하며, 폴더의 마지막 번호에 이어 붙인다. H1 제목도 파일명과 동일하게 번호 포함.
