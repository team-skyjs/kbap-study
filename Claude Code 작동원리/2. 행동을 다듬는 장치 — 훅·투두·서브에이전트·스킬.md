# 2. 행동을 다듬는 장치 — 훅·투두·서브에이전트·스킬 (s04~07)

> 맥락: 1번의 "돌아가는 최소 루프"에 실무용 능력 4가지를 얹는다.
> 목표: **"루프는 안 건드리고, 능력만 바깥에 매단다"** 는 설계 철학을 코드로 이해.

## 0. 한 줄 요약
**루프는 안정된 핵심으로 두고 확장은 훅과 도구로 바깥에 매단다** + **뒤로 갈수록 컨텍스트(토큰) 아끼기가 강조된다.**
- s04 훅: 부가기능을 루프 밖 "이벤트 콜백"으로 분리
- s05 투두: 실행이 아닌 "계획 능력"을 주는 도구
- s06 서브에이전트: 큰 일을 독립 컨텍스트로 분리 (맥락 오염 방지)
- s07 스킬: 지식을 필요할 때만 불러오기 (토큰 절약)

---

## 1. 핵심 개념

| | s04 훅 | s05 투두 | s06 서브에이전트 | s07 스킬 |
|---|---|---|---|---|
| 문제 | 부가기능마다 루프 수정 | 긴 작업서 목표 잊음 | 큰 조사가 컨텍스트 오염 | 지식 다 넣으면 토큰 낭비 |
| 해결 | 이벤트 콜백으로 분리 | 계획 전용 도구 | 독립 messages[] | 필요할 때만 로딩 |
| 키워드 | 확장점 | 계획 | 맥락 격리 | 2단계 로딩 |

## 2. s04 — 훅 (확장점)

부가기능(로그, 권한, 자동 git add)마다 루프를 고치면 루프가 너덜너덜. 훅은 확장 로직을 **루프 밖 "이벤트별 콜백 목록"** 으로 뺀다. 루프는 "이 시점 됐다"고 **알리기만** 하고, 뭘 할지는 등록된 훅이 결정.

이벤트 4개: `UserPromptSubmit`(입력시) · `PreToolUse`(도구 직전) · `PostToolUse`(직후) · `Stop`(종료 직전)

```python
def trigger_hooks(event, *args):
    for callback in HOOKS[event]:       # 이 이벤트에 등록된 콜백들
        result = callback(*args)
        if result is not None:          # None아니면 = 차단/개입 신호
            return result               # 나머지 콜백 건너뜀
    return None                         # 전부 None이면 통과
```

s03의 하드코딩 권한검사를 대체한 **유일한 변화**:
```python
blocked = trigger_hooks("PreToolUse", block)   # check_permission을 대체
if blocked:
    results.append({"type":"tool_result", "tool_use_id":block.id, "content":str(blocked)})
    continue                                    # 차단시 실행 안 함
```

> 비유: **컨베이어 벨트(루프)** 는 그대로 두고, 벨트 옆 지점마다 **센서(훅)** 를 매단다. 새 검사는 벨트를 뜯지 않고 센서만 추가.

> [!warning] 헷갈리는 반환값 규칙
> `None`=통과, `None아님`=개입인데 **이벤트마다 개입의 뜻이 다름.** PreToolUse의 non-None="실행 차단", Stop의 non-None="종료 막고 계속". 실제 CC는 이벤트가 27개이고, 훅이 "allow"해도 settings의 deny/ask는 못 뚫음(보안 계층).

## 3. s05 — TodoWrite (계획)

긴 다단계 작업을 주면 에이전트가 중간에 원래 목표를 잊는다(툴 결과가 컨텍스트를 채워 초기 계획이 밀려남). `todo_write`는 **아무 실제 작업도 안 하는** 도구 — 할 일을 적고 상태를 갱신하며 스스로 궤도 유지.

```python
def run_todo_write(todos):
    global CURRENT_TODOS
    todos, error = _normalize_todos(todos)   # JSON 문자열로 와도 관대하게 파싱
    if error: return error
    CURRENT_TODOS = todos                     # 그냥 메모리에 저장이 전부
```

3라운드간 갱신 없으면 자동 잔소리:
```python
if rounds_since_todo >= 3 and messages:
    messages.append({"role":"user", "content":"<reminder>Update your todos.</reminder>"})
    rounds_since_todo = 0
```

> 비유: 요리 전 화이트보드에 "①손질 ②볶기 ③플레이팅" 적고 하나씩 체크. 화이트보드가 요리를 해주진 않지만 순서를 안 놓치게 함.

> [!note] 주의
> 계획 능력만 줄 뿐 **실행 능력이 아님**(파일 안 바뀜). 목록은 휘발성(끄면 사라짐). "3라운드 잔소리"는 순전히 교육용 장치 — 실제 CC엔 없음.

## 4. s06 — 서브에이전트 (맥락 격리)

버그 하나 고치려 30개 파일 읽으며 60라운드 대화하면 messages가 중간단계로 가득 차 원래 목표를 잊음. 서브에이전트 = **"새 터미널 열어 조사만 시키고, 결론 한 줄만 받아오기".** `task` 도구가 담당: 새 messages[]로 독립 실행, **요약 텍스트만** 반환.

```python
def spawn_subagent(description):
    messages = [{"role":"user", "content":description}]  # 부모 이력 없는 새 컨텍스트
    for _ in range(30):                                   # 무한루프 방지 30턴 상한
        response = client.messages.create(model=MODEL, system=SUB_SYSTEM,
            messages=messages, tools=SUB_TOOLS)          # SUB_TOOLS엔 task 없음(재귀 방지)
    result = extract_text(messages[-1]["content"])
    return result                                         # 요약만, 중간이력 폐기
```

```python
blocked = trigger_hooks("PreToolUse", block)   # 서브에이전트도 권한 훅은 거침
```

> 비유: 바쁜 팀장이 인턴에게 "테스트 프레임워크 뭔지 조사해와". 인턴은 자기 책상(독립 컨텍스트)에서 20개 문서 뒤지지만 "pytest 씁니다" 한 줄만 보고. 팀장 책상은 깨끗.

> [!warning] 격리의 범위
> **맥락 격리 ≠ 부작용 격리**: 대화는 버려도 파일 쓰기/수정은 실제로 남음.
> **맥락 격리 ≠ 권한 격리**: 서브에이전트도 권한 훅 통과해야 함.

## 5. s07 — 스킬 로딩 (2단계 로딩)

프로젝트마다 React/SQL 가이드 등 지식이 다름. 전부 시스템 프롬프트에 넣으면(6500줄) 매 호출마다 관계없는 문서로 토큰 낭비. **2단계로 분리:**
- **레벨1(항상, 쌈)**: 시작 시 "목록"만 = 이름+한 줄 설명 (~100토큰/스킬)
- **레벨2(필요시, 비쌈)**: 에이전트가 `load_skill` 부를 때만 전체 내용 (~2000토큰/스킬)

```python
def build_system():
    catalog = list_skills()                    # 이름+설명만
    return f"...Skills available:\n{catalog}\nUse load_skill when needed."

def load_skill(name):
    skill = SKILL_REGISTRY.get(name)           # 경로 아닌 레지스트리 조회(경로탈출 방지)
    return skill["content"] if skill else f"Skill not found: {name}"
```

> 비유: **도서관 사서**. 입구엔 "책 제목 목록"만, 손님이 지목하면 그때 서고에서 그 책 한 권만 꺼내줌.

> [!important] 핵심 차이
> 스킬 내용은 **시스템 프롬프트가 아니라 tool_result로** 대화에 들어감. → 대화 이력에 남아 나중에 압축/잘림 대상이 됨(시스템 프롬프트는 안 사라짐). 이 차이가 [[3. 컨텍스트·기억·복원력]]의 압축과 연결됨.

## 6. 용어집
- **훅(Hook)**: 특정 시점에 자동 실행되게 등록해둔 확장 콜백. `HOOKS` 레지스트리에 이벤트별로 담김.
- **PreToolUse / PostToolUse**: 도구 실행 직전/직후 이벤트.
- **TodoWrite**: 할 일 목록·상태(pending/in_progress/completed) 관리하는 계획 전용 도구.
- **Subagent**: 부모와 분리된 자체 messages[]로 도는 독립 에이전트.
- **컨텍스트 격리**: 중간 대화를 부모에 안 섞어 주의력을 지키는 것.
- **Skill / SKILL.md**: 특정 지식·절차를 담은 마크다운(YAML frontmatter 포함).
- **2단계 로딩**: 목록은 항상 싸게(시스템 프롬프트), 내용은 필요시만 비싸게(tool_result).

> [!note] 2026-08-26 갱신 — 인용하던 kbap 사례가 바뀌었다
> 이 노트는 kbap-server 를 "서브에이전트로 역할을 나눠 TDD 를 굴리는 하네스"의 실사례로 인용했었다. 그 하네스(`tdd-harness-orchestrator` → `test-writer`(Red) → `implementer`(Green))는 **2026-08-14 제거**됐다 — 레포 `CLAUDE.md` 첫 절이 사유를 **"구현 단계가 느려지고 과한 코드가 나오는 문제"**로 못 박는다. 느려짐은 위 4절이 말한 맥락 격리의 대가 그대로다(에이전트마다 이미 읽은 파일을 처음부터 다시 읽는다). 과한 코드는 더 미묘하다 — `implementer` 는 **남이 쓴 테스트**를 받으니 "통과시키는 최소 구현"의 최소가 어디인지 판단할 근거가 없고, 안전하게 가려고 방어 코드·추상화를 얹는다.
> 지금 kbap 은 **메인 세션이 직접 구현**하고, 리뷰만 `kbap-code-review`·`kbap-db-review` **스킬로 명시 호출**한다. 즉 이 노트의 네 장치 중 kbap 에 남은 조합은 **스킬(필요할 때만 로딩) + 리뷰 전용 서브에이전트**다 — 리뷰어는 구현자의 사고를 물려받지 **않는 편이 낫고**, 사람이 부를 때만 도니 파이프라인을 늦추지 않는다. 헌법 원칙 I(Test-First: Red→Green→Refactor)은 그대로 유효하며 직접 구현에서 지킨다. **강제 수단(하네스)과 규칙(헌법)을 분리해 뒀기에 수단만 갈아치울 수 있었다.**
