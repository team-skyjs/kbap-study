# 1. 에이전트의 심장 — 루프·도구·권한 (s01~03)

> 맥락: `learn-claude-code`의 첫 3개 레슨. AI 코딩 에이전트의 **뼈대**를 만든다.
> 목표: "에이전트가 대체 뭘로 돌아가는가"를 코드 수준까지 이해하기.

---

## 0. 한 줄 요약
**에이전트는 "모델이 도구를 부르면 → 실행하고 → 결과를 되돌려주는" 무한 루프(s01)가 전부다.**
여기에 도구를 여러 개로 늘리고(s02), 실행 직전 안전 검문소(s03)를 얹는다.
**핵심: 루프 본체는 s01 이후 20레슨 내내 거의 안 바뀐다. 나머지는 전부 이 위에 얹는 "확장".**

> [!tip] 이 레포를 관통하는 큰 그림
> 매 레슨 = "이전 코드 전부 + 새 조각 하나". 누적 구조라, 루프가 안 바뀐다는 걸 기억하면 20레슨이 안 무섭다.

## 1. 핵심 개념

| | s01 루프 | s02 도구 | s03 권한 |
|---|---|---|---|
| 한다 | 생각→행동 반복 엔진 | 도구를 1개→5개로 | 실행 전 안전 검사 |
| 왜 | 모델은 말만 하지 실행 못함 | bash 하나로 다 짜면 낭비·오류 | 모델을 "믿음"으로 못 지킴 |
| 루프 변화 | (본체) | **한 줄** 바뀜 | **한 줄** 추가 |

`★ 핵심 통찰 ─────────────────────────────`
LLM은 "이 명령을 실행하라"는 **텍스트만** 뱉는다. 실제 실행하고 결과를 다시 보여주는
중간 다리는 사람이 복붙으로 하던 일. 그걸 코드로 자동화한 게 에이전트 루프.
즉 에이전트의 정체는 대단한 지능이 아니라 **30줄짜리 루프** — 지능은 모델에 있다.
`──────────────────────────────────────`

## 2. s01 — 에이전트 루프 (엔진)

### 작동 원리 (신호등은 딱 2개)
1. 사용자 질문을 첫 메시지로 넣음 → `messages = [{"role":"user", ...}]`
2. 메시지 + 도구정의를 모델에 보냄
3. 모델 답을 messages에 추가하고 **`stop_reason`을 봄**
   - `!= "tool_use"` (도구 안 부름) → **끝, 루프 탈출**
   - `== "tool_use"` (도구 부름) → 계속
4. 요청된 도구를 실제 실행 → 출력 수집
5. 출력을 `tool_result`로 포장해 넣고 → **2번으로 되돌아감**

```python
def agent_loop(messages):
    while True:                                     # 에이전트의 엔진
        response = client.messages.create(model=MODEL, system=SYSTEM,
                                          messages=messages, tools=TOOLS)
        messages.append({"role": "assistant", "content": response.content})
        if response.stop_reason != "tool_use":      # 도구 안 불렀으면 = 작업 완료
            return
        # ... 도구 실행 후 결과 되먹임 ...
```

도구 실행 → 되먹임 부분:
```python
output = run_bash(block.input["command"])           # 모델이 준 명령 실행
results.append({"type": "tool_result",
                "tool_use_id": block.id, "content": output})  # 결과 포장
messages.append({"role": "user", "content": results})  # 되먹임 → 루프 반복
```
- `tool_use_id`: "어느 도구 호출에 대한 결과인지" 짝을 맞추는 ID. 없으면 모델이 인식 못 함.
- 되먹임 메시지의 role이 `"user"`인 게 헷갈리는데, API 규약상 도구 결과도 user로 넣는다.

> 비유: **요리사(모델) + 주방보조(루프)**. 요리사는 "양파 썰어와"라고 *말만* 한다.
> 실제 칼질은 보조가 하고, 썬 걸 다시 보여주고, 요리사가 "됐어" 할 때까지 왕복 반복.

## 3. s02 — 도구 사용 (공구함)

bash 하나로 파일 읽기(`cat`)·쓰기(`echo >`)·찾기(`find`)를 다 짜면 번역 한 겹 더 끼어 낭비·오류.
그래서 `read_file`, `write_file`, `edit_file`, `glob` 전용 도구를 추가. **근데 루프는 안 바뀐다.**

비법 = 하드코딩 `run_bash()`를 **"이름 → 함수" 전화번호부(딕셔너리)** 로 교체:
```python
TOOL_HANDLERS = {"bash": run_bash, "read_file": run_read,
                 "write_file": run_write, "edit_file": run_edit, "glob": run_glob}

handler = TOOL_HANDLERS.get(block.name)              # 모델이 부른 이름으로 함수 찾기
output = handler(**block.input) if handler else f"Unknown: {block.name}"
```
- `handler(**block.input)`: 모델이 준 인자 딕셔너리를 풀어 함수에 전달. → **도구 추가 = 딕셔너리에 한 줄.**
- ⚠️ 그래서 도구 정의의 필드 이름과 함수 매개변수 이름이 **정확히 같아야** 한다.

파일 도구엔 탈출 방지 장치:
```python
def safe_path(p):
    path = (WORKDIR / p).resolve()
    if not path.is_relative_to(WORKDIR):            # 작업폴더 밖이면
        raise ValueError("Path escapes workspace")  # 거부 (../../etc/passwd 차단)
    return path
```

> 비유: **공구함**. s01은 맥가이버칼(bash) 하나로 다 하느라 어설프고, s02는 드라이버·망치를 갖춤.
> `TOOL_HANDLERS`는 공구함 뚜껑의 "라벨→칸" 지도 — 새 공구는 라벨 한 줄만 추가.

## 4. s03 — 권한 (검문소)

안전은 "모델을 믿는다"로 못 지킨다("정리해줘" → `rm -rf /` 가능). 그래서 **실행 직전 3관문**:

1. **Gate 1 · 거부목록**: `rm -rf /`, `sudo`, `mkfs` 등 **절대 금지** → 즉시 차단, 묻지도 않음
2. **Gate 2 · 규칙매칭**: "상황따라 위험" (작업폴더 밖 쓰기, `rm`/`chmod 777`) → Gate 3로 넘김
3. **Gate 3 · 사용자 승인**: `Allow? [y/N]` 로 사람에게 물음
   → 셋 다 안 걸리면 그냥 실행 (읽기 등 일상 작업)

```python
def check_permission(block):
    if block.name == "bash":                         # Gate 1
        if check_deny_list(block.input.get("command","")):
            return False                             # 즉시 차단
    if check_rules(block.name, block.input):         # Gate 2
        if ask_user(...) == "deny": return False     # Gate 3: 사람에게 물음
    return True
```

루프에 추가된 **유일한 한 줄**:
```python
if not check_permission(block):
    results.append({"type":"tool_result", "tool_use_id":block.id,
                    "content":"Permission denied."})   # 실행 대신 거부 결과 반환
    continue                                          # 다음 도구로
```
- 거부돼도 모델에게 "거부됨"을 알려줘서 다른 방법을 시도하게 함.

> 비유: **공항 보안검색대**. Gate1=무기 무조건 압수(협상불가), Gate2=액체·노트북 따로 분류,
> Gate3=요원이 "열어봐도 될까요?" 질문. 아무것도 안 걸린 승객은 그냥 통과.

## 5. 주의점 / 교육용 vs 실제 Claude Code

- **루프가 "지능"이라 착각 금지.** 지능은 모델, 루프는 실행-되먹임 골격일 뿐.
- 실제 CC는 스트리밍에서 `stop_reason`이 늦게 갱신돼서, 대신 응답에 `tool_use` 블록이 있는지 직접 검사(`needsFollowUp`).
- 실제 CC는 읽기전용 도구를 **병렬** 실행(`isConcurrencySafe`). 교육용은 순차.
- **문자열 거부목록은 진짜 보안이 아님** — `rm  -rf  /`(공백)·별칭·셸확장으로 우회됨. 데모임.
- 실제 CC 권한 결과는 4종류(`allow`/`deny`/`ask`/`passthrough`), 규칙 출처도 8곳에서 병합, 자동모드는 분류기 LLM(YoloClassifier)이 판단.

## 6. 용어집
- **Agent Loop**: 모델호출→도구실행→결과되먹임 반복 while 루프. 에이전트의 핵심 골격.
- **stop_reason**: 모델 응답 종료 이유. `"tool_use"`면 도구 부름 = 루프 계속.
- **tool_result / tool_use_id**: 도구 결과 메시지 / 어느 호출의 결과인지 짝짓는 ID.
- **Tool Dispatch**: 도구 이름으로 실행 함수를 찾아 부르는 것 (`TOOL_HANDLERS`).
- **Tool Definition**: 도구의 이름·설명·입력스키마. 모델에게 주는 사용설명서.
- **Permission Pipeline**: 실행 전 거부→질문→허용 순 검사 체계.
- **Deny List / Rule Matching**: 무조건 금지 목록(Gate1) / "이럴 땐 물어라" 규칙(Gate2).

## 7. 한 줄 복습
> 루프(엔진)는 안 바뀐다. 도구는 딕셔너리에 한 줄, 권한은 루프에 한 줄. 확장은 전부 이 위에 얹힌다.
