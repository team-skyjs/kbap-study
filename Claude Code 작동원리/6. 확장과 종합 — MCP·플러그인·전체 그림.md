# 6. 확장과 종합 — MCP·플러그인·전체 그림 (s19~20)

> 맥락: 외부 도구를 표준으로 연결(s19)하고, 20레슨 전부를 하나의 루프로 재조립(s20).
> 목표: 전체를 관통하는 **"하네스 엔지니어링"** 철학을 손에 쥐기.

## 0. 한 줄 요약
**s19는 표준 프로토콜(MCP)로 외부 도구를 도구 풀에 끼워 넣는 법을, s20은 s01~19의 모든 장치를 단 하나의 `while True` 루프 주위에 다시 조립하는 법을 가르친다.**

`★ 이 레포 전체의 대전제 ─────────────────`
**"행위 능력(agency)은 코드가 아니라 모델 훈련에서 나온다."**
`에이전트 제품 = 모델(운전자) + 하네스(차량)`. 우리가 하는 일은 지능을 코딩하는 게 아니라,
이미 똑똑한 모델이 능력을 발휘하도록 **도구·지식·관찰·행동·권한**을 갖춘 환경을 짓는 것 = "하네스 엔지니어링".
if-else와 노드 그래프로 LLM을 엮어 "에이전트를 만든다"는 착각(프롬프트 배관)을 정면 비판.
Claude Code가 우아한 이유 = **"에이전트가 되려 하지 않고" 모델에게 도구만 쥐여주고 물러나기** 때문.
`──────────────────────────────────────`

## 1. s19 — MCP 플러그인 (외부 도구, 표준 프로토콜)

s01~18의 모든 도구는 사람이 손으로 짠 것. Jira·사내배포·Notion 같은 외부 서비스를 붙일 때마다 새로 짜는 건 낭비. **MCP(Model Context Protocol)** = "외부 서비스가 이 표준만 지키면 무슨 언어든 에이전트가 바로 호출" 하는 공용 규격. 핵심 동작 2개: 목록 받기(`tools/list`), 실행(`tools/call`).

```python
def assemble_tool_pool():
    tools = list(BUILTIN_TOOLS); handlers = dict(BUILTIN_HANDLERS)
    for server_name, mcp_client in mcp_clients.items():
        for tool_def in mcp_client.tools:
            prefixed = f"mcp__{server_name}__{tool_def['name']}"   # 네임스페이싱(충돌 방지)
            tools.append({"name": prefixed, ...})
            handlers[prefixed] = (lambda *, c=mcp_client, t=tool_def["name"], **kw:
                                  c.call_tool(t, kw))              # 기본값 인자로 값 고정
    return tools, handlers
```
- ⚠️ `c=mcp_client, t=...`: 람다 **기본값 인자로 값 고정** → 반복 변수가 나중에 바뀌어도 각 핸들러가 올바른 값 기억(late-binding 클로저 버그 방지).

`connect_mcp` 이후 도구 풀이 바뀌므로 s10부터 쓰던 **캐시를 버림**:
```python
if any(b.name == "connect_mcp" for b in response.content if b.type == "tool_use"):
    tools, handlers = assemble_tool_pool()   # 연결 직후 도구 풀 재조립
```

> 비유: 전동 드릴 비트 갈아끼우기. 드릴 본체(루프)는 그대로, 육각 소켓 표준(MCP)만 맞으면 남이 만든 어떤 비트(외부 도구)든 꽂아 바로 씀.

> [!note] 교육용 목업
> 실제 MCP는 서브프로세스+stdin/stdout JSON-RPC, 6종 전송, OAuth, 재연결이 있지만 여기선 Python 함수로 흉내만. 권한도 텍스트(`readOnly`)만 붙일 뿐 안 막음(강제는 s20 hook에서).

## 2. s20 — 종합 에이전트 (모든 장치를 하나의 루프로)

앞 19장은 학습 위해 장치를 하나씩만 켰지만, 진짜 에이전트는 **전부 동시에** 필요. s20의 교훈: "기능을 쌓는 것"이 아니라 **"각 장치가 루프의 어디에 붙는지"** 보기. **새 메커니즘은 하나도 없음. 오직 조립.**

**루프 한 바퀴의 순서:**
1. 크론 큐 주입(`[Scheduled]`) → 2. 백그라운드 알림 주입(`<task_notification>`) → 3. 컨텍스트 압축 파이프라인 → 4. 시스템 프롬프트 재조립(정체성+도구+스킬+메모리+MCP) → 5. LLM 호출(에러복구로 감쌈) → 6. tool_use 없으면 `Stop` 훅 후 종료 → 7. 있으면 `PreToolUse` 훅(권한) → 느리면 백그라운드/아니면 실행 → `PostToolUse` 훅 → 결과 붙이고 다음 바퀴

권한이 실행 라인에 하드코딩 안 되고 **훅으로 분리**된 게 정수:
```python
blocked = trigger_hooks("PreToolUse", block)   # 권한·로그·감사가 여기 다 붙음
if blocked:
    results.append({"type":"tool_result", "tool_use_id":block.id, "content":str(blocked)})
    continue
```
종료 판단은 `stop_reason`이 아니라 **실제 tool_use 블록 존재**로:
```python
def has_tool_use(content):
    return any(getattr(b, "type", None) == "tool_use" for b in content)
```

> 비유: 자동차 대시보드 조립. 엔진(모델)과 크랭크축(while 루프)은 s01부터 그대로. s20은 그 축 주위에 계기판·에어백·내비·크루즈컨트롤을 올바른 위치에 장착하는 **최종 조립** — 엔진 교체가 아니라 운전 환경 완성.

> [!important] 두 종류씩 꼭 구분
> **두 위임**: `task`(일회용 서브에이전트, 맥락 격리·요약만) vs `spawn_teammate`(지속 스레드, MessageBus, 작업보드 폴링).
> **두 계획**: `todo_write`(세션용 경량, 메모리) vs 작업 그래프(`.tasks/*.json`, 의존성·크로스세션).
> plan 승인 게이트는 **실제로 막음**: 팀원이 `submit_plan` 후 Lead 승인 전까진 스텝 정지(`waiting_plan` 게이트).

## 4. 용어집
- **MCP**: 에이전트가 외부 도구를 발견/호출하는 표준 규격.
- **도구 풀(tool pool)**: 모델에게 넘기는 사용 가능 도구들의 최종 합본.
- **네임스페이싱**: `mcp__server__tool` 접두어로 동명 도구 충돌 방지.
- **하네스(harness)**: 모델 주위를 감싸는 운영 인프라 전체(루프·도구·권한·기억·팀·MCP).
- **훅**: 루프를 안 고치고 도구 전후·시작종료에 끼우는 확장점. 권한도 여기 하나로.
- **압축 파이프라인**: 큰출력 예산→잘라내기→축약→LLM요약 다단계.
- **RecoveryState(에러복구)**: 429 백오프, 529 폴백모델, max_tokens 상향, prompt-too-long 즉석압축.
